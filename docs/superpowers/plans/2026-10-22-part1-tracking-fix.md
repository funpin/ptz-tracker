# Шаг Б, часть 1: слежение без отставания и ложной раскачки

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** камера держит идущего человека у центра кадра, не теряет его и не раскачивается. Ложных «РАСКАЧКА» и «Калибровка…» нет. Зум не уезжает на общий план на ходу.

**Основание:** разбор части 0 — `docs/field/2026-10-22-part0-analysis.md`.

**Что сейчас.** Сценарий «walk», «Пояс · центр», «Обычно», 22 с:

| Симулятор | Средняя ошибка | Худший момент |
|---|---|---|
| плоский | 0,125 кадра | 0,44 кадра |
| с перспективой (теперь по умолчанию) | 0,084 кадра | 0,31 кадра |

**Spec:** `docs/superpowers/plans/2026-10-22-step-b-tracking-and-control.md` (часть 1).

## Global Constraints

- **Инварианты эфира** (AGENTS.md):
  - ручное действие, Esc и смена камеры выключают слежение до следующей команды;
  - стопы не теряются;
  - поток Qt не ждёт сеть.
- **Поворот важнее зума.** Путь `pt` — не дольше одного окна 130 мс (p95 сейчас ~130 мс, это нужно сохранить). Зуму можно дать окно, но поворот не задерживать больше чем на одно окно.
- **Пороги и коэффициенты** меняются только с записью «было → стало, почему, какой тест» в `docs/DECISIONS.md`.
- **Тесты регулятора:**
  - сначала виртуальное время `tests/control/loop.py`, рассогласование камеры `speed_factor` 0,5…2, задержка очереди `cmd_delay`;
  - затем симулятор с перспективой (`slow`);
  - тесты не ослаблять, чтобы прошли.
- **Факты камеры** — только в `camera/he42.py`.

## Review Focus

1. **Отставание на ходу.** Обычная ходьба 0,5–1,2 м/с, «Пояс», «Обычно».
   - Средняя ошибка ≤ 0,05 кадра, не считая первой 1 с после начала ходьбы: часть 0 показала, что старт быстрее не догнать.
   - Человек не ближе 0,15 кадра к краю.
   - Зум на ходу не отъезжает больше чем в 1,3 раза.
2. **Без раскачки при ошибке калибровки ×0,5…×2.** Сторож не срабатывает. Разворотов камеры за 10 с стояния — не больше одного.
3. **Модель зума совпадает с камерой.** Масштаб в модели отличается от `#GZ` меньше чем на 10%. Наезд не продолжается, когда человек пошёл.
4. **Мастер калибровки:**
   - задержка видео в пределах ±0,05 с от правды симулятора;
   - τ в пределах ±0,1 с;
   - камера в конце там же, где была в начале (±1°);
   - на однотонной стене мастер не уводит камеру.
5. **Остановка человека.** Перелёт ≤ 0,08 кадра, без рывка назад. Покачивание у кафедры камеру не двигает.

### Task 1: Модель зума — по отправленным командам и `#GZ` (Opus)

**Files:**
- `control/framing.py` — `_zoom`, `zdyn`;
- `control/follower.py`;
- `camera/scheduler.py` — окно для зума;
- тесты `tests/control/test_framing.py`, `tests/camera/test_scheduler.py`, `tests/control/test_follower.py`.

**Что сделать:**
- `zdyn` получает команду зума в момент **отправки** (через `on_sent` планировщика), а не в момент решения.
- Положение `zdyn` подправляется по каждому ответу `#GZ`.
- В планировщике: если зум ждёт дольше 0,3 с, а команда `pt` не менялась заметно (меньше 2 кодов), зум получает окно. Поворот не ждёт больше одного окна.
- Наезд прекращается, как только человек пошёл, даже если команда наезда ещё в очереди.

**Тесты:**
- `test_zoom_model_follows_sent_not_decided` — виртуальное время, `cmd_delay` у зума 1,5 с: модель совпадает с камерой;
- `test_zoom_gets_window_without_delaying_pan_beyond_one_slot`;
- `test_no_zoom_in_while_walking`.

### Task 2: Сторож раскачки — только настоящие развороты (Opus)

**Files:** `control/framing.py` (`_Axis`, `WATCHDOG_*`); тест `tests/control/test_framing.py`.

**Разворот засчитывается, только если:**
- команда переходит через порог, при котором камера реально едет (|v| > 0,03 fw/s);
- зум сейчас не едет;
- ошибка больше всей мягкой зоны;
- ошибка растёт от разворота к развороту.

Дополнительно — подтверждение по `#APC`: реальные развороты камеры.

**Тесты:**
- `test_watchdog_ignores_reversals_below_moving_speed`;
- `test_watchdog_ignores_reversals_during_zoom`;
- `test_watchdog_still_catches_real_divergence_x2` — рассогласование ×2 и ×3: срабатывает;
- повтор записей части 0 — 9 из 10 ложных тревог уходят, настоящая остаётся. Эпизоды положить в `tests/data/episodes/`, если влезают в размер.

### Task 3: Мастер калибровки по положению камеры (Opus)

**Files:** `control/calibration.py`, `diagnostics/probe.py` (только общий код); тесты `tests/control/test_calibration.py`.

**Что сделать:**
- Перед замером разгона ждать, пока `#GZ` перестанет меняться, а не фиксированные 2 с.
- Задержку видео меньше 0,05 с не принимать: взять значение по виду потока и предупредить в журнале калибровки.
- Между пробегами возвращать камеру в исходную точку (`#APS`) и ждать по `#APC`.
- Скорость мерить по `#APC` (градусы/с) и переводить в доли кадра по углу обзора на этом зуме. Картинка — только для задержки видео и проверки.
- Вместо «максимума предыдущих» отбрасывать выбросы и проверять, что скорость растёт с кодом.
- Однотонная стена больше не ломает замер скоростей.

**Тесты:**
- `test_wizard_returns_to_start` (±1°);
- `test_wizard_latency_matches_sim` (±0,05 с);
- `test_wizard_tau_matches_sim`;
- `test_wizard_on_flat_wall_does_not_drift` — сцена без текстуры.

### Task 4: Догонять без отставания — упреждение, ускорение, потолок, торможение (Opus)

**Files:**
- `control/framing.py` — константы и `_Axis.step`;
- `control/effort.py`;
- тесты `tests/control/test_framing.py`, `tests/control/test_closed_loop.py`.

**Что сделать:**
- `FF_GAIN` → 1,0.
- `a_max` около 1,0 fw/s² для «Обычно»: плавность задаётся ограничением рывка, а не запретом разгона.
- `v_max` — по возможностям камеры (0,8–1,2 fw/s по таблице на текущем зуме).
- Торможение с учётом тормозного пути камеры: τ и мёртвое время модели. Без этого перелёт ~0,6 кадра.
- «Пошёл» узнавать по скорости и направлению за 0,3–0,5 с; покачивание по-прежнему не двигает камеру.
- «Мягко ↔ Резко» меняет плавность и зоны, но не запрещает догонять.

**Тесты:** Review Focus 1, 2 и 5 в виртуальном времени (`speed_factor` 0,5 / 1 / 2) и на симуляторе с перспективой.

### Task 5: Подстройка скорости во время слежения (Opus)

**Files:**
- новый `control/speed_adapt.py`;
- `control/follower.py`;
- `config.py` — поправка в калибровке камеры;
- тесты `tests/control/test_speed_adapt.py`.

**Что сделать:**
- Сравнивать команды поворота с фактическим движением по `#APC` на отрезках, где камера ехала ровно не меньше 0,5 с.
- Плавно поправлять множитель таблицы «код → скорость» по оси pan (и tilt) с ограничением ×0,5…×2.
- Сохранять поправку в калибровку камеры не чаще раза в минуту.

**Тесты:**
- камера на самом деле в 1,6 раза быстрее таблицы: за 30 с ходьбы поправка подходит к 1,6 ± 0,15, раскачки нет;
- без движения поправка не меняется.
