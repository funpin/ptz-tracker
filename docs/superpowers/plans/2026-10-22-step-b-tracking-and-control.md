# Шаг Б: надёжное слежение, свои зоны, крупность ползунком, управление с клавиатуры, мыши и геймпада

Статус: одобрен пользователем 2026-10-22 с правками (ПКМ — только зум/ирис; выход из режима мыши — Tab или Esc). Код — только после «да» пользователя. Порядок жёсткий: пока не закрыты раскачка и отставание (части 0–1), остальное не начинаем.

## Что не так сейчас (замер на симуляторе, 2026-10-22)

Сценарий «идёт — стоит — идёт обратно», «Пояс · центр», «Обычно»:

| | откалибровано | без калибровки |
|---|---|---|
| средняя ошибка по горизонтали | 0,125 кадра | 0,120 кадра |
| худший момент | 0,44 кадра (человек у края) | 0,35 кадра |
| зум на ходу | уезжает на общий план | то же |

Причины, найденные в коде:
1. **Потолок скорости.** «Обычно» не даёт камере ехать быстрее 0,5 ширины кадра в секунду. Идущий человек на «Поясе» движется в кадре на ~0,7.
2. **Упреждение вполовину** (`FF_GAIN = 0,5`). Камера по замыслу едет вдвое медленнее человека и догоняет только за счёт ошибки.
3. **Поздний старт.** Камера трогается, только когда человек вышел из мёртвой зоны и прошёл заметное расстояние за 1,5 с; разгоняется медленно.
4. **Отъезд у края.** Отставший человек оказывается у края кадра, и программа сразу отъезжает шире. Отсюда «Пояс уезжает почти на общий план».
5. **Слабые тесты.** Они допускали ошибку до 0,40 кадра и потому этого не ловили.
6. **Сторож раскачки** срабатывает и после калибровки (замечание пользователя). Причина не установлена — разбирается в части 0.
7. **Симулятор двумерный** и совпадает с моделью регулятора по построению. Перспективу, дисторсию объектива и неточную калибровку он не проверяет.

О задержке: камера получает команды сразу, с задержкой приходит только картинка. Программа вычитает задержку видео, но не держит команды. Между командами есть пауза 130 мс — это требование Panasonic (~7 команд/с). Часть 0 измерит, нет ли лишней задержки по пути: очередь, соединение, ответ камеры.

3. **Перспектива.** Сделать симулятор проективным: поворот камеры — гомография по углам pan/tilt, плюс дисторсия объектива и угол обзора по зуму. На нём повторить замеры. Это же закрывает замечание о «2D-тестах».

## Часть 1. Слежение без отставания и раскачки

Исправления — по итогам части 0. Ожидаемые:
- **Скорость.** Потолок — по реальным возможностям камеры (до ~1,2 кадра/с при рабочем зуме), а не 0,5. «Мягко ↔ Резко» задаёт плавность разгона, а не запрет догонять.
- **Упреждение** почти полное. Устойчивость при неточной калибровке даёт подстройка скорости во время слежения: программа сравнивает команду с фактическим движением по `#APC` (раз в 0,5 с уже опрашивается) и плавно поправляет таблицу «код → скорость». Это «докалибровка в процессе», о которой просил пользователь. Поправка ограничена (×0,5…×2) и сохраняется в калибровку камеры.
- **Ранний старт:** ходьбу узнавать по скорости и направлению за 0,3–0,5 с, покачивание у кафедры по-прежнему не двигает камеру.
- **Отъезд у края** — только если камера уже едет на пределе и человек всё равно уходит. Без рывка на общий план.
- **Сторож раскачки** — по факту: развороты камеры по `#APC` плюс рост ошибки, а не только развороты команды.
- **Мастер калибровки:** между пробегами камера возвращается в исходную точку (`#APS`), скорость меряется по положению `#APC`, а не по картинке. Не уводит камеру на однотонную стену.
- **Опорная точка** — лицо, а не живот: якорь кадра считается от головы и плеч и виден на превью.

**Критерии готовности** (тесты в виртуальном времени и на проективном симуляторе):
- обычная ходьба (0,5–1,2 м/с): средняя ошибка ≤ 0,05 кадра, человек не подходит к краю ближе 0,15 кадра, зум на ходу не отъезжает;
- остановка: перелёт ≤ 0,08 кадра, без возврата рывком;
- калибровка ошибочна в 0,5–2 раза: без раскачки, сторож не срабатывает;
- покачивание у кафедры: ни одного движения камеры;
- задержка H.264: держит человека в кадре.

**Контрольная точка:** показываю пользователю запись симулятора «до/после» и цифры. Затем проверка на площадке по `LIVE_TEST_PROMPT.md` и донастройка по живым записям.

## Часть 2. Свои зоны и крупность

- **Зоны перетаскиваются мышью на превью:**
  - мёртвая зона (синяя) и мягкая (оранжевая) — переносом и за углы;
  - точка «где должно быть лицо» — переносом.

  Сохраняется для камеры и для выбранной крупности. Кнопка «Сбросить зоны». Пока оператор тянет зону, слежение не выключается, но и камера не дёргается: изменения применяются плавно.
- **Крупность — ползунок с картинками** вместо кнопок «Кадр». Три силуэта-ориентира: **1-й средний** (по грудь), **2-й средний** (по пояс/колени), **общий** (в рост). Ползунок плавный, между ними — любая крупность.
- **Положение в кадре** (слева / центр / справа) — три маленькие кнопки рядом с ползунком. Тонкую настройку даёт перетаскивание точки лица.
- **Клавиши Z / X / C** — 1-й средний / 2-й средний / общий.

## Часть 3. Управление камерой

**Клавиатура (окно активно, курсор не в поле ввода):**

| Клавиши | Действие |
|---|---|
| 1–9 | вызвать пресет камеры |
| Shift + 1–9 | записать пресет |
| W A S D и стрелки | поворот, пока держите; Shift — быстрее |
| + / − | зум |
| Z X C | крупность |
| Пробел | слежение вкл/выкл |
| Esc | стоп камеры |
| F1 | окно с горячими клавишами |
| F9 | сохранить момент |

**Режим «камера как курсор» (мышь):**
- **Вход:** клавиша **Tab** или двойной клик по видео. Курсор прячется, по краю видео — цветная рамка «УПРАВЛЕНИЕ МЫШЬЮ».
- **Выход:** **Tab** или **Esc** (Esc заодно останавливает камеру). При выходе камера сразу останавливается. Если окно теряет фокус, камера останавливается, а режим остаётся до Tab или Esc.
- **Движение мыши** → скорость камеры (как ведёте — так и едет), с мёртвой зоной от дрожания руки. Остановили руку — камера плавно остановилась.
- **Колесо** — зум или ирис (см. ПКМ).
- **ЛКМ** — взять в слежение человека в центре кадра (или ближайшего к центру) и включить слежение.
- **ПКМ** — переключить колесо: зум ↔ ирис. Текущий режим подписан в рамке.

Любое ручное движение, как и сейчас, выключает автоматическое слежение.

**Геймпад** — Sony DualSense (PS5), USB или Bluetooth; через SDL2 GameController, без отдельного окна. Раскладка пользователя (2026-10-29):

| Кнопка | Действие |
|---|---|
| левый стик | поворот (скорость — по отклонению) |
| L2 / R2 | зум шире / ближе; скорость — от силы нажатия (аналоговые курки DualSense) |
| ✕ ○ □ △ | пресеты 1 2 3 4: короткое нажатие — вызвать, долгое (~1 с) — записать |
| крестовина ← / → | взять в слежение соседнего человека левее / правее текущей цели |
| L1 / R1 | крупность: шире / ближе (1-й средний ↔ 2-й средний ↔ общий) |
| Options | меню камеры на экране; в меню: крестовина — выбор, ✕ — принять, ○ или △ — отмена (кнопки пресетов в меню не работают) |
| *нет в раскладке* | **стоп камеры** и **слежение вкл/выкл** — предложение: нажатие тачпада — стоп, R3 (нажатие правого стика) — слежение; подтвердить с пользователем |

Если геймпад отключили, камера сразу останавливается.

**Окно «Горячие клавиши» (F1):** схема клавиатуры, мыши и геймпада с подписями по-русски, отдельно для режима «камера как курсор».

## Решения (подтверждены 2026-10-22)

1. Режим мыши: вход — Tab или двойной клик по видео; выход — Tab или Esc.
2. ЛКМ в режиме мыши берёт в слежение человека в центре кадра и включает слежение.
3. Слева / центр / справа — три кнопки рядом с ползунком крупности.
4. Геймпад — через SDL2 (pygame-ce, LGPL).
5. Порядок: часть 0 → часть 1 → проверка «до/после» → площадка → части 2–3.

## Как работаем

- **Код:** субагенты по задачам; механические задачи — Sonnet, регулятор и потоки — Opus. Каждая задача — с ревью, в конце — общее ревью.
- **Порядок в задаче:** сначала тест, который падает. Регулятор проверяем сначала в виртуальном времени, затем на проективном симуляторе.
- **Пороги и коэффициенты** меняются только с записью «почему» в `DECISIONS.md`.
- **Подробные планы задач** (формат этапов 1–3) пишутся на каждую часть после этого одобрения.
