# Этап 2: зона — граница, регулятор без обгона и «насоса» — план реализации

> **Исполнителю:** обязательный навык — `superpowers:executing-plans` (одна сессия: задачи 2–6 правят один и тот же
> `_Axis.step`), в конце независимое ревью всей работы. Шаги — флажками `- [ ]`.
> **Статус:** одобрено оператором 2026-11-11, зона — **вариант Б**. Коммиты — только с его согласия.

**Цель:** камера держит человека внутри зоны, которую задал оператор, не обгоняет его на остановке, ведёт наклон как
поворот, зум не ходит «отъехал — наехал».

**Архитектура:** регулятор остаётся чистой функцией шага (`FramingController.step`). Меняются три вещи: (1) он знает
своё «позднее знание» `T` и держит идущего впереди точки на `v·T`; (2) пороги догона и ускорения считаются от границы
зоны и времени до неё, одинаково для поворота и наклона; (3) зум получает устойчивый размер и терпение. Стенд учится
тому, чего в нём нет: поворот боком, камера быстрее модели, разные потоки и зоны.

**Стек:** Python 3.13, numpy, pytest, PySide6 (только плашка зоны). Новых зависимостей нет.

**Спека:** `docs/superpowers/specs/2026-11-10-stage2-zone-boundary-regulator-design.md`. Макет:
`docs/design/mockups/zone-boundary.html`.

## Общие ограничения

- Инварианты `AGENTS.md`: стопы не теряются, ручное действие выключает слежение, сторож раскачки (`SwingWatch`) и его
  пороги не меняются, поток Qt не ждёт сеть.
- Сигнатуры `FramingController.step(FramingInput) -> FramingOutput`, `zoom_sent`, `pt_sent` не меняются.
- Подбор чисел — только по `SEEDS["настроечные"]`; `SEEDS["отложенные"]` запускаются в задаче 7 и больше нигде.
- Каждое новое или изменённое число — строка с замером в `docs/DECISIONS.md`; отложенное — в `docs/BACKLOG.md`.
- Пороги существующих тестов не ослаблять. Тест мешает — остановиться и спросить оператора.
- Ключевые точки — numpy float32: перед арифметикой `float(...)`.
- Живую камеру не двигать без слов оператора «не в эфире». Коммит и push — только с его согласия (шаги «Коммит» ниже —
  после согласия, иначе пропускаются).
- После каждой задачи: `.venv/bin/pytest -q -m "not slow"` и `.venv/bin/ruff check src tests`.

## Review Focus

1. Камера вдвое быстрее или медленнее модели и задержка видео неверна на ±0,1 с — без раскачки и без срабатывания
   сторожа (`test_goals_hold_when_camera_model_is_wrong`, задача 3).
2. Точка не в центре («Пояс · слева») и широкая зона: граница зоны дальше края кадра — граница обрезается по краю
   кадра минус 0,06 (`test_zone_is_cut_by_frame_edge`, задача 5).
3. Кадры приходят неровно (две камеры делят нейросеть, `meas_jitter=0.05`) — оценка `T` не скачет больше чем на 20 %
   (`test_late_knowledge_survives_irregular_frames`, задача 2).
4. Оператор тянет зону во время слежения — камера доезжает плавно, без рывка и без выключения слежения
   (`test_zone_change_while_following_is_smooth`, задача 5).
5. Человек пропал на ходу и появился — запас «впереди точки» не даёт рывка (`test_reacquire_after_loss_no_jump` остаётся
   зелёным; добавить случай с ходьбой 0,5 кадра/с, задача 3).

### Задача 3: закон оси — поворот

**Файлы:** изменить `src/ptztracker/control/framing.py` (`_Axis.step`, `_Axis._ramp`, константы), создать
`tests/control/test_axis_law.py`; изменить `tests/control/test_operator_eye.py`, `tests/control/test_zone_boundary.py`.

**Берёт:** `FramingController.t_late` (задача 2). **Даёт:** `_Axis.step(..., zone: float, t_late: float)` — `zone`
вместо `soft` как граница; `_Axis.lead_now: float` (запас впереди точки, для записи и тестов).

Новые числа: `LEAD = 0.8`, `LEAD_ZONE_SHARE = 0.6`, `A_CAMERA = 8.0` (кадра/с²), `ROOM_MIN = 0.02`. Уходят:
`FF_RISE_S`, `CATCH_UP`, `CATCH_UP_RUSH`, `RUSH_FROM`, `RUSH_TO`, `CATCH_UP_FROM`, `CATCH_UP_TO`, `FB_WALK_BASE`,
`FB_WALK_K`, `FB_EDGE_FROM`, `FB_EDGE_TO`, `RETURN_V_MAX`, `LEAD_MAX`, `LEAD_TAU`, `EffortProfile.lead`.

Закон (остальное в `step` — как сейчас: цель-смесь, пауза перед разворотом, доводка `hold`, доворот за зумом, поиск):

```
v_w   = w * moving_img                                   # скорость идущего в кадре
lead  = clamp(LEAD * v_w * t_late, ±LEAD_ZONE_SHARE * zone)   # человек впереди точки, в сторону хода
x     = err - lead                                       # что выбирает поправка
v_rel = v_w - sign * dyn.velocity(now) * k_now           # человек относительно камеры
room  = max(zone - reach - abs(v_rel) * (dyn.dead_time + dyn.tau), ROOM_MIN)
a_need = v_rel**2 / (2 * room) if v_rel * err > 0 else 0.0   # идёт к границе
a_lim = max(e.a_max, min(a_need, A_CAMERA));  j_lim = e.j_max * a_lim / e.a_max
v_fix = hold * copysign(min(abs(speed_for_error(x, dead, zone, e.gain, v_cap)), sqrt(2 * BRAKE * a_lim * abs(x))), x)
want  = sign * (v_w + v_fix)                             # дальше — _ramp с a_lim, j_lim вместо boost
```
