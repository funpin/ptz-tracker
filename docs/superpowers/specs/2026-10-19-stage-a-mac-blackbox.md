# Шаг А: запуск на Mac, «чёрный ящик» и доступ агента к живой камере

Статус: черновик на согласование (2026-10-19).

## Зачем

Слежение на площадке работает нестабильно: цель теряется и перескакивает на других людей, камера дёргается, при композиции «Пояс» уезжает на широкий план. Калибровка уводит камеру на однотонную стену. Сейчас разработчик видит только скриншоты, а по ним причину не найти: неизвестно, что видела нейросеть, какую цель выбрал трекер и какие команды ушли на камеру. Этот шаг даёт:

1. **Чёрный ящик.** Программа постоянно записывает последние минуты работы. Оператор нажимает одну кнопку — «Сохранить момент», и запись становится файлом для разбора.
2. **Повтор записи на Mac.** Записанный эпизод прогоняется через распознавание и регулятор без камеры. Плохой эпизод с площадки становится тестом, который должен начать проходить после исправления.
3. **Работа на MacBook пользователя с живой камерой.** Если ноутбук в одной сети с камерой, агент сам калибрует, записывает и проверяет слежение на живых данных.

## 1. Запуск на Mac

Код уже запускается на macOS: симулятор работает, пути к настройкам задаёт `platformdirs`, пароли хранит `keyring` (на Mac это «Связка ключей»). Нужно:

- **Нейросеть.** В `vision/pose_detector.py` добавить `CoreMLExecutionProvider` (на M-чипе он есть в onnxruntime 1.31). Если он не стартует — CPU, как сейчас с DirectML. В «Диагностике» показывать, на чём работает нейросеть.
- **Видео.** Проверить MJPEG и RTSP через PyAV на Mac с живой камерой (основной путь — MJPEG).
- **Запуск.** Скрипт `run_mac.command`: двойной клик запускает программу из `.venv`. Сборка `.app` не нужна: программу на ноутбуке запускает сам пользователь или агент.
- **Сеть.** macOS при первом обращении к локальной сети спрашивает разрешение. Это нужно описать в инструкции.

## 2. Чёрный ящик (`ptztracker/recorder/`)

**Что пишется** — каждое событие с меткой времени `monotonic`:

| Поток | Частота | Содержимое |
|---|---|---|
| Кадры | 5 к/с, JPEG 640×360 качества 70 | картинка + `t_capture`, `seq` |
| Анализ | каждый результат | люди: рамки, ключевые точки, уверенность, номера; цель и её состояние |
| Регулятор | 25 Гц | вход (опорная точка, U, зум), выход (pan/tilt/zoom, состояние, ошибки), профиль «Мягко↔Резко», композиция |
| Команды | каждая отправка | текст команды (`#PTS…`, `#Z…`), приоритет, ответ камеры, время в очереди |
| Положение камеры | раз в 0,3 с, когда идёт слежение | `#APC` (pan/tilt) и `#GZ` (зум) — **факт**, а не модель |
| События | по факту | вкл/выкл слежения и причина, выбор и сброс цели, сторож раскачки, смена композиции |

Пароли и адреса с паролями в запись не попадают (`redact_url`).

**Формат.** Папка эпизода с файлами `meta.json` (версия программы, камера без пароля, калибровка, настройки), `events.jsonl` и `frames/000123.jpg`. Каждый эпизод упаковывается в один zip, как отчёт диагностики.

**Кольцевой буфер.** В памяти хранятся последние **5 минут** (около 40 МБ). Кнопка «Сохранить момент» (клавиша `F9`) сохраняет буфер в zip в папку «Записи PTZ Tracker» на рабочем столе. Включено ли постоянное сохранение на диск, задаётся в настройках (по умолчанию — выкл., ~450 МБ/час).

**Нагрузка.** Запись идёт в отдельном потоке, JPEG кодируется там же. Поток Qt, регулятор и анализ кладут события в очередь и не ждут: если очередь переполнена, кадр выбрасывается, а события регулятора — нет.

## 3. Повтор записи (`ptztracker --replay запись.zip`)

- **Режим «анализ».** Кадры записи заново идут через детектор и трекер, результат сравнивается с записанным: так видны перескоки цели и потери.
- **Режим «регулятор».** Записанные результаты анализа идут через текущий `FramingController`, получаются новые команды; для них строятся графики ошибки и команд (PNG). Так проверяется, что исправление убирает рывки на реальном эпизоде.
- **Просмотр.** Окно повтора: кадр с рамками и командами, перемотка, скорость ×0,25–×4.
- Короткие эпизоды (5–20 с) кладутся в `tests/data/episodes/` и становятся медленными тестами (`slow`).

## 4. Доступ агента к живой камере

Агент (Claude Code на том же MacBook) работает через командную строку и локальный API.

**Команды без окна** — для работы, пока камера не в эфире:
- `ptztracker --diagnose --ip …` — уже есть;
- `ptztracker lab calibrate --ip …` — калибровка с записью в файл;
- `ptztracker lab record --ip … --seconds 60` — запись без движения: видео, распознавание, положение камеры;
- `ptztracker lab follow --ip … --seconds 60` — слежение с записью.

**Локальный API главного окна** — `127.0.0.1`, порт из настроек, ключ в файле конфигурации:
- только чтение (по умолчанию): состояние, цель, ошибки, последние события, «Сохранить момент»;
- управление (переключатель **«Разрешить управление агенту»** в окне, по умолчанию выкл., сбрасывается при перезапуске): вкл/выкл слежения, композиция, «Мягко↔Резко», запуск калибровки.

**Безопасность эфира:**
- Все команды движения от агента идут с флагом «камера НЕ в эфире», который ставит оператор в окне.
- Esc и любое ручное действие по-прежнему выключают слежение. Кроме того, они выключают «Разрешить управление агенту».
- API слушает только `127.0.0.1`, без ключа отвечает 401.

## 5. Что не входит

Исправления слежения (шаг Б), свои зоны (шаг В), редизайн (идёт в отдельной сессии). На этом шаге в интерфейсе появляются только кнопка «Сохранить момент», переключатель «Разрешить управление агенту» и строка о записи. Их оформление потом унифицирует редизайн.

## 6. Как проверяем

- Модульные тесты: формат записи, кольцевой буфер, обрезка паролей, отбрасывание кадров при переполнении.
- Симулятор: запись 30 с слежения → повтор в режиме «регулятор» даёт те же команды (детерминизм).
- Тест нагрузки: с записью частота анализа на симуляторе не падает больше чем на 5%.
- Площадка: пользователь запускает программу на Mac, ведёт докладчика 2–3 минуты, нажимает F9 и присылает zip.
