# Главное окно: компактная верхняя панель, всё нужное без прокрутки, кнопка питания

Дата: 2026-10-30. Статус: черновик, ждёт одобрения пользователя.
Макет показан пользователю в чате 2026-10-30 («да, мне нравится»).

## Зачем

Оператор прислал скриншот v0.3.1: верхняя панель забита длинными надписями («Нет видео (адрес 5 из 6): [Errno 1094…]», «ATEM · нет связи», «анализ: загрузка…», «запись 5 мин»), они не влезают. Часть действий лежит в меню macOS «Сервис», часть — в окне. Важные во время эфира органы (ирис, пресеты, фокус) прячутся под прокруткой правой панели. Когда камера стоит в режиме ожидания (standby), программа показывает непонятную ошибку RTSP вместо «камера выключена — включить?».

## Что оператор смотрит и трогает (его слова)

- **Смотрит в эфире:** какая камера выбрана, разрешение и частота кадров видео, подключён ли ATEM, скорость анализа.
- **Трогает в эфире:** поворот камеры (джойстик в программе, позже геймпад PS5), зум, ирис, gain, пресеты; реже — фокус и баланс белого.
- **Не должно быть так, чтобы за важной функцией приходилось прокручивать интерфейс.**
- «Слежение» — в верхнюю панель, самым правым, иконкой; можно короткие английские ON/OFF.
- «Запись 5 мин» сбивает: похоже на запись видео (она тоже в планах), а на деле это логи чёрного ящика.
- Меню macOS «Сервис» убрать: всё — в одной кнопке меню внутри окна, одинаково на Mac и Windows.

## Цели

1. Верхняя панель в одну строку, без обрезанных надписей при ширине окна 1640 (и не ломается до ~1280): иконка + 1–2 коротких слова; подробности и тексты ошибок — во всплывающей подсказке.
2. Правая панель без прокрутки при окне 1640×850: все органы эфира видны сразу.
3. Одна схема действий: редкие действия — в кнопке меню ☰ в окне; верхнее меню macOS пустое (кроме системного меню приложения).
4. Камера в standby → в области видео круглая кнопка питания и понятная подпись.

## Не цели

- Код регулятора и слежения (`framing/`, `control/`) не трогаем: только интерфейс и состояние питания камеры.
- Геймпад PS5 — отдельная работа (часть 3 плана step-b).
- Запись видео — отдельная будущая функция; здесь только освобождаем для неё слово «запись».
- Не меняем горячие клавиши.

## Анти-цели (провал, даже если «работает»)

- Аварийный стоп перестал быть всегда на виду.
- Ошибка или потеря связи стала незаметной: убрали текст — цвет значка обязан сразу показать беду (красный).
- Поток Qt ждёт сеть ради опроса питания.
- Выключение камеры в standby одним случайным кликом или во время слежения.

## Как устроено окно

### Верхняя панель (слева направо)

| Элемент | Вид | По клику | Подсказка (tooltip) |
|---|---|---|---|
| Камера | значок камеры + имя + ▾ (выпадающий список, как сейчас) | выбор камеры | IP, состояние связи и питания |
| Управление камерами | иконка-кнопка (шестерёнка/настройки) | меню: Добавить… / Изменить… / Удалить… | «Камеры: добавить, изменить, удалить» |
| — растяжка — | | | |
| Видео | иконка + «1280×720 · 25» (короткая запись; формат — решение строителя, напр. «720p · 25») | меню выбора потока (сейчас комбобокс «Видео: Авто») с галочкой у текущего | поток (MJPEG/H.264), адрес без пароля, текст ошибки целиком |
| Анализ | иконка + «14 к/с» | — | задержка мс, устройство (DirectML/CPU), «загрузка модели…» |
| ATEM | иконка + «ATEM» или «ATEM 3 · PGM» / «· PVW» | открыть настройку ATEM | текущий длинный текст `tally_chip` |
| Чёрный ящик | только иконка (история/часы), без текста | меню: Сохранить момент (F9) / Открыть запись… / Настройки записи… | «Чёрный ящик: хранит логи последних N мин. F9 — сохранить» |
| Агент | значок «AGENT», **виден только когда «Разрешить управление агенту» включено** | открыть панель агента | состояние двух флажков |
| Меню ☰ | иконка; точка-метка, если есть обновление | меню (см. ниже) | |
| Слежение | крупнее остальных: иконка прицела + «TRACK ON» (зелёный) / «TRACK OFF» (нейтральный); клавиша «Пробел» в подсказке | вкл/выкл слежение (как Пробел) | подсказка-инструкция «Кликните по человеку, затем Пробел»; причина, если включить нельзя |

Цвет значка показывает состояние: зелёный — норма, жёлтый — предупреждение/загрузка, красный — ошибка/нет связи, серый — не настроено/выключено. Текст ошибки нигде в панели не печатается — только в подсказке и в окне видео (см. ниже).

Чипа «Нет связи с камерой» больше нет: состояние связи показывает цвет значка у имени камеры и область видео.

### Меню ☰

Калибровка камеры… · Диагностика камеры… · ATEM… · Агент… · Включить камеру / Перевести камеру в режим ожидания… · Проверять обновления (галочка) · «Доступна версия X» (если есть; открывает страницу релиза). Пункты чёрного ящика дублируются здесь же подменю «Чёрный ящик».

Меню macOS «Сервис» удаляется. Горячая клавиша F9 продолжает работать (shortcut вешается на окно, а не на пункт меню macOS).

### Область видео

- Поверх видео в углах — маленькие кнопки: «Сбросить цель» (иконка) и «Скелет» (переключатель-иконка). Раздел «Цель» из правой панели убирается; текст «Цель: не выбрана — кликните…» показывается в подсказке TRACK и поверх видео, пока цель не выбрана (коротко).
- Нет видео (ошибка) — как сейчас, но текст человеческий: «Нет видео с камеры KZ_PTZ_2» + вторая строка мелко с причиной; полный технический текст — в подсказке значка «Видео».
- **Камера в standby** — вместо ошибки: круглая кнопка питания по центру, под ней «Камера KZ_PTZ_2 найдена, но выключена (режим ожидания)» и «Нажмите, чтобы включить». После нажатия — «Камера включается…» до появления видео; кнопка неактивна, пока идёт включение.
- Рамка Tally (красная/зелёная) — как сейчас.

### Правая панель (без прокрутки при 1640×850)

Сверху вниз:
1. **Кадр** — пять кнопок 1–5 в одну строку (короткие подписи/иконки; полное имя в подсказке), «Мягко — Резко». Жёлтая строка «Камера не откалибрована…» — только когда это правда.
2. **Камера** — джойстик и зум рядом (как сейчас, компактнее).
3. **Ирис** — ползунок + «Авто».
4. **Gain** — ползунок/шаги + «Авто». *(новое)*
5. **Пресеты** — кнопки 1–8 одной строкой (Shift+клик — записать).
6. **Фокус** — ползунок/кнопки «ближе/дальше» + «AF», «разовый AF».
7. **Баланс белого (WB)** — режим (Авто / пресеты) и/или цветовая температура. *(новое)*
8. Внизу закреплён «СТОП КАМЕРЫ · Esc» (как сейчас).

Блок «Слежение — ВЫКЛ» сверху правой панели убирается (переехал в TRACK). Панель «Агент» уходит в меню ☰ → «Агент…» — **немодальное** окошко или выдвижная панель (модальный диалог нельзя: API отвечает 409, пока открыт диалог); флажки не сохраняются и сбрасываются как сейчас.

Сначала собрать без сворачивания и замерить высоту в тесте при 1640×850. Только если не влезает — допустимо сворачивание секций «Фокус» и «WB» в одну строку-заголовок (раскрываются кликом), но не прокрутка.

Строка состояния внизу с клавишами — остаётся.

## Питание камеры

Источник плана: `docs/superpowers/plans/2026-10-22-step-b-tracking-and-control.md`, часть 3 «Кнопка питания камеры» — эта спека реализует её.

- Состояние: уже идущий раз в 2 с запрос `#O` (`camera/session.py::_heartbeat`). Сейчас ответ не разбирается. По документации Panasonic: `p1` — включена, `p0` — standby, `p3` — идёт переключение. ⚠ проверить на живой HE42 через диагностику (добавить `#O` в отчёт) и записать в §7 спеки и `camera/he42.py`.
- Включить: `#O1`. Выключить (standby): `#O0` — только из меню ☰, с подтверждением, и только при выключенном слежении (если слежение включено — сначала выключить, как ручное действие).
- «Камера найдена, но выключена» = HTTP-запросы проходят и последний ответ на `#O` — `p0`. MJPEG в standby всё равно отдаётся (замер HE40), поэтому решает только `#O`. Включение: `p3` ~4 с, видео ~8 с. Если HTTP не отвечает — прежнее «нет связи».
- В standby программа показывает кнопку питания поверх видео, что бы ни приходило с видео. Переподключение видео не меняем: у HE40 MJPEG в standby продолжает идти (замер 2026-10-30), а RTSP сам переподключается после включения.
- Симулятор (`sim/`) получает состояние питания: по `#O0` перестаёт отдавать видео и отвечает `p0`, по `#O1` через короткую задержку возвращается.
- Время включения HE42 неизвестно ⚠ — подпись «Камера включается…» без обещания секунд.
- Ответ `p3` (переключение) → «Камера включается…» (или «выключается…»), кнопка неактивна. Любой другой/непонятный ответ на `#O` → прежнее поведение «нет видео» (чтобы неверная догадка о протоколе не спрятала настоящую ошибку). *(решение строителя-проверяющего)*
- В объём работы входят `camera/session.py` (разбор ответа `#O`, поле питания в снимке состояния, команды `#O1`/`#O0` через планировщик) и логика переподключения видео в standby. `framing/` и `control/` не трогаем.
- Пункт меню «Перевести камеру в режим ожидания…» всегда доступен; если слежение включено, клик сначала выключает его (как любое ручное действие), затем спрашивает подтверждение. *(моё решение)*

## Gain и баланс белого

Команды идут через `aw_cam` и **на живой HE42 не проверены** (⚠ в §7).

**Замер на живой AW-HE40 (Ver.1.54, клуб, 192.168.10.41, 2026-10-30, только запросы, без изменений):** авторизация не нужна. `#O` → `p1`. `QID` → `OID:AW-HE40`. `QGU` → `OGU:11` (усиление), `QAW` → `OAW:9` (режим баланса белого), `QSD:B1` → `OSD:B1:01A` (вероятно, цветовая температура), `QSD:48` → `OSD:48:32`, `QRV` → `ORV:3FF` (ирис), `QRS` → `ORS:0`, `QAF` → `OAF:1`, `#D1` → `d11`, `#D3` → `d30`, `#GI` → `giFFF0`. Не поддерживаются (`ER1`): `QBV`, `QSI:20`, `QSJ:4A`, `QAI`, `QIG`. MJPEG 640×360 отдаётся. Проба с изменениями (диапазоны gain, режимы WB, цветовая температура, standby/включение) — в §7 основной спеки. Gain и WB подключаются по этим замерам; подписи dB/кельвинов помечены ⚠ до сверки с меню камеры. Порядок: добавить их запрос в «Диагностику камеры», получить отчёт пользователя, записать в `camera/he42.py` и §7, затем включить ползунки. Решено (2026-10-30): подключаем по замеру на HE40. Gain — шаги по 3 dB + «Авто»; WB — режимы (Авто ATW / AWB A / AWB B / 3200K / 5600K / VAR) и ползунок температуры в режиме VAR. Ошибки `ER2`/`ER3` от камеры не ломают интерфейс: значение откатывается к запрошенному у камеры.

## Ограничения

- Окно ~1640×850; правая панель шириной как сейчас (`SIDE_WIDTH = 372`) или уже.
- Иконки — SVG-файлы в репозитории (набор Tabler Icons, MIT — совместим с AGPL-3.0; лицензию положить рядом), подключаются в `packaging/ptztracker.spec` как данные. *(моё решение)*
- Узкое окно (до ~1280): имя камеры и TRACK не сжимаются; первыми теряют текст значки Видео и Анализ (остаётся иконка), затем ATEM. *(моё решение)*
- Инварианты AGENTS.md: ручное действие/Esc выключают слежение до следующей команды; поток Qt не ждёт сеть (питание — через планировщик и снимок состояния); пароли не попадают в подсказки (адрес RTSP — с `***`).
- Существующие тесты UI (`tests/ui/`) обновляются под новые виджеты; поведение (Esc, ручное управление, tally) не меняется.
