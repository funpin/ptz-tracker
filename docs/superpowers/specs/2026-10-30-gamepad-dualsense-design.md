# Управление камерой с геймпада PS5 (DualSense)

Статус: реализовано (задачи 1–9 плана); итоговая раскладка уточнена пользователем 2026-10-30. Проверка на площадке — в `docs/LIVE_TEST_PROMPT.md`.
Источник: `docs/superpowers/plans/2026-10-22-step-b-tracking-and-control.md`, часть 3 «Геймпад» — эта спека её заменяет (раскладка от 2026-10-29 там устарела).

## Зачем

Оператор ведёт камеру в эфире: поворот, зум, ирис, gain, пресеты; реже — фокус и баланс белого. Мышью по экранному джойстику это медленно и неточно, клавиатура даёт только одну скорость. Геймпад даёт плавную скорость стиком и курками и позволяет не смотреть на экран: о состоянии говорит цвет световой полосы.

**Успех:** оператор весь эфир ведёт камеру с DualSense, не трогая мышь; программа при этом может быть не в фокусе (активно окно ATEM Software Control или OBS).

## Цели

1. DualSense по USB и Bluetooth на Windows и macOS; работает при неактивном окне программы.
2. Раскладка ниже, без настройки пользователем.
3. Световая полоса показывает состояние; вибрация подтверждает запись пресета.
4. Меню камеры на экране (кнопка Options) для редких настроек.
5. Схема геймпада — в окне «Горячие клавиши» (F1), подписи по-русски.

## Не цели

- Переназначение кнопок, другие геймпады (Xbox и пр. — могут заработать сами через SDL, но не проверяются и не обещаются).
- Несколько геймпадов одновременно: работает первый подключённый, остальные игнорируются.
- Цвет полосы по камере (у каждой камеры свой цвет) — не нужен (пользователь, 2026-10-30).
- Подсветка кнопки Mute — SDL 2 ею не управляет. (Белые точки «номер игрока» управляются — см. ниже.)

## Анти-цели (провал, даже если «работает»)

- Камера продолжает ехать после того, как стик отпущен, геймпад отключён, сел или программа закрылась.
- Слежение и движение с геймпада одновременно борются за камеру.
- Подвисание окна или видео из-за опроса геймпада.
- Нажатие кнопки, которое без подтверждения меняет то, чего оператор не просил (например, первое нажатие ириса сбрасывает яркость скачком).

## Раскладка (пользователь, 2026-10-30)

| Кнопка | Действие | Выключает слежение |

| L3 (нажатие левого стика) | разовая автофокусировка (`push_focus`) | нет |
| правый стик ← / → | цель — соседний человек левее / правее текущей | нет (см. ниже) |
| R3 (нажатие правого стика) | слежение вкл / выкл (как Пробел) | — |
| L2 / R2 | зум шире / ближе; скорость — от силы нажатия | да |
| R1 / L1 | стик быстрее / медленнее (пользователь, 2026-11-06): у каждого геймпада режим в ☰ → «Геймпады…» — «Предел скорости» (полный наклон = 25/50/75/100 %, вибрация — столько толчков, какая ступень) или «Чувствительность» (±10); на краю — длинный толчок. Только поворот и наклон, зум не меняется | нет |
| свайп по тачпаду → / ← | крупность шире / ближе — только размеры: вправо пояс → в рост → общий; влево назад, к последней стороне пояса (до 2026-11-06 — R1 / L1). Свайп: не меньше трети ширины, не дольше 0,8 с, по горизонтали больше, без нажатия тачпада | нет |
| ✕ ○ □ △ | пресеты 1 2 3 4: короткое нажатие — вызвать, удержание ~1 с — записать (вибрация) | да |
| крестовина ← / → | ирис закрыть / открыть на шаг | нет |
| крестовина ↑ / ↓ | gain выше / ниже на шаг 3 dB | нет |
| тачпад (нажатие) | стоп камеры (как Esc и кнопка «СТОП КАМЕРЫ») | да |
| Options | меню камеры на экране | — |
| Create (нажатие) | следующая камера (пользователь, 2026-10-30) | — |
| Create (удержание ~1 с) | сохранить момент, как F9 (пользователь, 2026-10-30) | нет |
| PS, Mute | не назначены | — |

**Отключили геймпад (кабель, Bluetooth, разряд)** — камера сразу останавливается: нулевые скорости поворота, зума и фокуса. Если в этот момент камера стояла, ничего не шлём. Слежение при этом не трогаем (стоп не аварийный — оператор мог отложить геймпад при включённом слежении).

### Подробности поведения

- **Стики и курки:** мёртвая зона ~0,12 по каждой оси, дальше линейно до 1 (можно квадратичную кривую для точной наводки на малых отклонениях — решает исполнитель, выбор с причиной в `DECISIONS.md`). Вертикаль стика: вверх — камера вверх. Команда скорости уходит только при изменении (как у клавиатуры, `only_if_changed`), не чаще такта опроса.
- **Ирис и gain** — шаг за нажатие; удержание — автоповтор (задержка ~0,4 с, затем ~6 шагов/с). Ирис: шаг ≈ 1/16 диапазона `LENS_MIN…LENS_MAX`. Если ирис на «Авто», первое нажатие переводит в ручной режим с **текущего значения камеры** (без скачка) и сразу делает шаг (перед абсолютным ирисом всегда шлём `iris_auto(False)`). **Gain из «Авто» (решение агента):** камера не отдаёт автоматическое значение (0x80), поэтому, если ручное значение ни разу не видели, нажатие ничего не меняет и даёт короткую вибрацию «некуда»; если видели — переключаем на последнее ручное значение. Оператору нужно один раз выставить gain в окне или меню.
- **Сосед правым стиком:** отклонение за ~0,6 — один шаг, следующий — только после возврата стика в центр. Сосед — ближайший по горизонтали (центр рамки) человек с нужной стороны среди видимых в последнем кадре; нет такого — ничего не делаем (короткая слабая вибрация «некуда»). Нет текущей цели — берём человека, ближайшего к центру кадра с нужной стороны. Если слежение включено, оно продолжается за новой целью; если выключено — цель только выбирается (включает R3). В запись чёрного ящика — событие `target` с `how="pad_left"/"pad_right"`.
- **Пресеты:** вызов — по отпусканию кнопки, если она была нажата меньше 1 с; запись — когда удержание достигло 1 с, без подтверждения на экране (подтверждение — вибрация ~0,2 с); после записи отпускание ничего не вызывает.
- **R3 при отсутствии цели** — как Пробел сейчас (тот же код `toggle_follow`).

## Меню Options

Кнопка Options открывает поверх видео в главном окне компактное меню камеры. Меню закрывается кнопками ○ и △. Ручной фокус за одно нажатие едет не дольше 3 с — геймпад не шлёт повторов, чтобы обновлять сторожа (решение агента). Пока меню открыто: крестовина ↑/↓ — пункт, ←/→ — значение, ✕ — принять/переключить, ○ или △ — закрыть; кнопки пресетов, ирис и gain на крестовине **не работают**; стики, курки, тачпад-стоп и R3 работают как обычно. Мышью и клавиатурой меню тоже управляется; горячая клавиша — решает исполнитель вместе с сессией редизайна окна (не должна конфликтовать с `_HOTKEYS`).

Правый стик (сосед) в меню тоже работает (решение агента). Пункты (выбор пунктов и порядок — решение агента, пользователь может поправить):
1. Фокус: Авто / Ручной; в ручном ←/→ — ближе/дальше (скорость, пока держишь, не дольше 3 с).
2. Баланс белого: Авто ATW / AWB A / AWB B / 3200K / 5600K / VAR; в VAR — цветовая температура ←/→.
3. Ирис: Авто / Ручной.
4. Gain: Авто / Ручной.

Меню закрывается само через ~10 с без нажатий. Если окно программы свёрнуто или под другим окном, меню всё равно работает — оператор видит результат в картинке; это ожидаемо.

## Световая полоса и вибрация (пользователь, 2026-10-30)

Цвет — состояние выбранной камеры; если совпало несколько, побеждает верхнее:

| Цвет | Когда |
|---|---|
| красный | камера в программе ATEM (`AtemTally`, вход камеры `atem_input`) |
| оранжевый, мигает ~1 Гц | нет связи с камерой или камера в режиме ожидания (standby) |
| фиолетовый | открыто меню Options |
| голубой | слежение включено |
| зелёный | камера в предпросмотре ATEM |
| тусклый белый | ручное управление, всё в порядке |

Tally здесь, как и везде, только визуальный: красный ничего не блокирует (решение 2026-10-22). Цвет ставится только при смене состояния. Если источника состояния ещё нет в коде (например, режим ожидания до работы по питанию камеры) — этот цвет просто не используется, пока источник не появится (решение агента). При закрытии программы полосе возвращаем нейтральный цвет.

### Белые точки «номер игрока» (пользователь, 2026-10-30)

Точки на геймпаде показывают номер текущей камеры (1…4): `CameraConfig.pad_number`, если задан в настройках камеры («Номер на геймпаде», пусто — авто); иначе цифры в конце названия («KZ_PTZ_2» → 2); иначе место камеры в списке. Ставится через `SDL_GameControllerSetPlayerIndex` (ctypes, `SdlBackend.set_player_index`) при подключении и смене камеры; без камеры — гасим. Create (короткое нажатие) переключает на следующую камеру, точки следуют за ней.

### Вибрация

Все паттерны — на полной силе (1,0 / 1,0), короткие — не короче 120 мс: слабее на живом DualSense не чувствуется (замер, решение агента).

| Сигнал | Когда |
|---|---|
| одна ~0,25 с | пресет записан |
| короткая (120 мс) | «некуда»: нет соседа с нужной стороны, нет значения gain, край списка крупностей |
| **две коротких** (120 мс, пауза 120 мс) | **слежение включилось** — с любого источника (R3, Пробел, кнопка, агент) (пользователь, 2026-10-30) |
| **одна длинная ~0,5 с** | **слежение выключилось само** — потеряна цель, сработал сторож раскачки и т. п.; не при выключении действием оператора (R3, Пробел, ручное движение, стоп) (пользователь, 2026-10-30) |
| **«упор»**: короткий импульс, повтор ~раз в 0,7 с, пока стик/курок давит в ту сторону | **камера уперлась в предел** поворота, наклона или зума, а оператор продолжает давить (пользователь, 2026-10-30) |

**Как узнаём упор (решение агента).** Пределы камеры не зашиваем: пока геймпад шлёт ненулевую скорость поворота/наклона, раз в ~0,2 с спрашиваем положение `#APC` (приоритет `QUERY`, фоновый поток, как опрос в `Follower`); если по оси, куда давим, положение за ~0,3 с не изменилось больше чем на 2 единицы при скорости, дающей заметный сдвиг, — это упор. Для зума то же по `#GZ` (на краях 0x555 / 0xFFF — сразу упор). Опрос идёт только пока стик отклонён; во время калибровки (`quiet_for_calibration`) — не идёт. Симулятор уже упирается (`PAN_LIMIT`, `TILT_MIN/MAX`, края зума) — на нём и тест.

## Как устроено (решения агента — архитектура)

**Библиотека: pygame-ce** (LGPL-2.1, внутри SDL 2.32, zlib) — уже выбрана в плане step-b (решение 4). Проверено 2026-10-30 на Mac в чистом venv: pygame-ce 2.5.8 / SDL 2.32.10, у `pygame._sdl2.controller.Controller` есть `set_led(color)` и `rumble(...)`; SDL даёт `SDL_HINT_JOYSTICK_ALLOW_BACKGROUND_EVENTS` (работа без фокуса) и HIDAPI-драйвер PS5. На живом DualSense ещё не проверено. Нельзя ставить рядом `pysdl2-dll`: две копии SDL в одном процессе (на Mac — дубли классов Objective-C, возможны падения). pygame-ce импортируется лениво и только модулем геймпада; если её нет или SDL не стартовал — программа работает без геймпада, в журнале одна строка. Видео/окна pygame не инициализируются — только `joystick`/`controller`; приветствие pygame в консоли подавить (`PYGAME_HIDE_SUPPORT_PROMPT`).

**Потоки.** Модуль `ptztracker/gamepad/` без Qt:
- фоновый поток опроса ~100 Гц (`SDL_GameControllerUpdate`/события), раскладка → намерения (`PanTilt(vx,vy)`, `Zoom(v)`, `Preset(n, store)`, `IrisStep(±1)`, `GainStep(±1)`, `Neighbor(±1)`, `ToggleFollow`, `Stop`, `PushFocus`, `Composition(±1)`, `Menu…`, `Disconnected`);
- чистая функция/автомат «сырое состояние кнопок и осей + время → намерения» (мёртвая зона, удержание пресета, автоповтор, шаг соседа) — тестируется без SDL и без железа;
- выход для цвета/вибрации — очередь команд в тот же поток (SDL-устройство трогает только поток опроса).

В Qt намерения приходят **очередным сигналом** (`QueuedConnection`) в `MainWindow`, который вызывает те же методы, что клавиатура: `session.set_pan_tilt_velocity`, `set_zoom_velocity`, `recall_preset`/`store_preset`, `emergency_stop()` окна, `toggle_follow`, `_on_composition`. Так геймпад автоматически получает инвариант «ручное действие выключает слежение и снимает флажки агента **до** отправки команды» (`CameraSession._manual` → `on_manual`) — тем же путём, что и клавиатура; новых путей к камере нет. Поток Qt ничего не ждёт: методы сессии только кладут команду в планировщик.

**Стопы не теряются.** `Disconnected`, выход потока опроса по исключению и закрытие программы дают нулевые скорости (поворот, зум, фокус меню) через обычный путь `MANUAL`; планировщик уже гарантирует, что стоп не теряется. Если поток опроса упал — он сначала шлёт `Disconnected`, затем пишет ошибку в журнал. Тачпад — `MainWindow.emergency_stop()`, как Esc.

**Несколько источников скорости (решение агента).** Клавиатура, экранный джойстик и геймпад — разные «держатели». `MainWindow` хранит скорость каждого источника отдельно и отправляет в сессию сумму с ограничением ±1 по каждой оси (на практике одновременно работает один); отпускание одного источника не обнуляет другой. `release_all_held()` обнуляет только клавиатуру и мышь и переотправляет итог. Стоп (тачпад, Esc, кнопка) обнуляет все источники, включая запомненное состояние геймпада: чтобы камера снова поехала, стик нужно вернуть в центр.

**Когда геймпад выключает слежение (решение агента).** Любая ненулевая скорость за мёртвой зоной — через тот же `set_pan_tilt_velocity`/`set_zoom_velocity`, что выключает слежение до отправки. Если оператор включил слежение R3, держа стик, оно сразу выключится при следующем изменении скорости — ручное управление всегда главнее. Дрейф стика гасит мёртвая зона.

**Меню Options (решение агента).** Виджет поверх видео, не диалог. Для API считается «открытым диалогом» (агент получает 409, пока меню открыто) — безопаснее. Смена камеры или стоп закрывают меню.

**Удержание пресета** отменяется, если за это время сменилась камера, открылось меню или нажат стоп (решение агента).

**Сосед** — новый метод анализатора `select_neighbor(direction)` под его замком, по трекам последнего результата (те же номера, что `select_at`) (решение агента).

**Запуск и упаковка (решение агента).** pygame-ce — обычная зависимость в `pyproject.toml` (обе ОС). Поток опроса — демон, стартует при открытии окна, останавливается в `closeEvent` (после отправки нулей). SDL инициализируется в потоке опроса; если пробник покажет, что на macOS так нельзя, — опрос по `QTimer` ~100 Гц в потоке Qt (`SDL_GameControllerUpdate` не блокирует, микросекунды) — решает первая задача плана.

**Неактивное окно.** Сейчас `changeEvent(ActivationChange)` вызывает `release_all_held()` — для клавиатуры и мыши это остаётся. Для геймпада деактивация окна **не** отпускает стики: его состояние живёт в модуле геймпада, а не в `_held`. Проверить, что `release_all_held()` не обнуляет скорости, которые сейчас держит геймпад (иначе при переключении в ATEM камера дёрнется стопом и тут же поедет снова) — согласовать: кто «держит» скорость, тот её и обнуляет.

**Смена камеры** — намерения адресуются текущей `self.session`; при смене камеры старой уходят нули (как сейчас `release_all_held` при смене), стики надо вернуть в центр, чтобы новая поехала.

**Gain и баланс белого.** (Историческая запись; позже работа по главному окну влилась, крестовина ↑/↓ и пункты меню Gain/WB работают.) Команд для них в коде ещё нет; их добавляет работа по спеке `2026-10-30-main-window-layout-design.md` (gain — шаги 3 dB + Авто; WB — режимы и VAR; по замеру на HE40). Геймпад использует методы сессии оттуда. Геймпад их не дублирует: пока у сессии нет этих методов, крестовина ↑/↓ и пункты Gain/WB в меню неактивны; подключение — отдельная задача после слияния той работы (уточнено при планировании 2026-10-30). Шаги ириса — новый метод сессии `iris_step(±1)` поверх `set_iris`.

**Окно «Горячие клавиши» (F1)** — две таблицы: клавиатура (`_HOTKEYS`) и геймпад (`GAMEPAD_HELP` в `ui/hotkeys_dialog.py`).

**Состояние в интерфейсе (пользователь, 2026-10-30).** Чип в верхней панели после значка чёрного ящика: номер камеры, заряд и оценка («2 · 60% · ≈3 ч 10 мин», «заряжается», «считаю…», пока оценка не набралась). Заряд — из сырого отчёта DualSense (шаг 10 %), оценка — по скорости падения. Без геймпада чип скрыт. Заряд ≤ 20 % — жёлтый. Сообщение при первом подключении в журнал: имя, тип (`PS5`), USB/Bluetooth, наличие LED.

## Ограничения

- Python 3.12–3.13, Windows и macOS; PyInstaller: проверить, что `pygame` попадает в `packaging/ptztracker.spec` (у pygame-ce есть хуки PyInstaller) и что сборка CI запускается на Windows без геймпада.
- AGPL-3.0: pygame-ce LGPL — совместимо; отметить в списке зависимостей/лицензий, если он есть.
- Окно ~1640×850 — чип и меню не увеличивают высоту.
- Живая камера с машины разработчика недоступна; живого DualSense у агента тоже нет — вся логика проверяется на симуляторе и подставном «геймпаде» (сырые состояния осей/кнопок).

## Проверка

- Юнит-тесты автомата «кнопки → намерения»: мёртвая зона, курки, удержание пресета (короткое/долгое, запись не вызывает после отпускания), автоповтор ириса/gain, шаг соседа с возвратом в центр, меню блокирует пресеты/ирис/gain, приоритет цвета полосы.
- Тесты окна (pytest-qt) с подставным источником намерений и симулятором: поворот с геймпада выключает слежение до первой команды движения; отключение геймпада → нулевые скорости; деактивация окна не останавливает движение с геймпада; тачпад = аварийный стоп; R3 = Пробел; флажки агента снимаются.
- Вибрация: две коротких при включении слежения с любого источника; «упор» на симуляторе — стик держат вправо у `PAN_LIMIT`, импульсы идут, после отпускания прекращаются; опрос положения не идёт при отпущенном стике.
- Сосед: тест анализатора на сцене симулятора с несколькими людьми.
- Ручная проверка пользователем на площадке (шаг в `docs/LIVE_TEST_PROMPT.md`): USB и Bluetooth, Windows и Mac, окно ATEM в фокусе, выдернуть кабель на ходу, цвета полосы.
- Первая задача плана — короткий пробник `python -m ptztracker --lab gamepad` (без камеры): печатает имя, тип, оси, кнопки, ставит цвета по кругу, вибрирует. Пользователь запускает его с DualSense на Mac и Windows и присылает вывод — до остального кода. Если что-то из обещанного (фон, LED, Bluetooth) не работает — вернуться к пользователю до продолжения.

## Оставлено исполнителю

Точные числа мёртвой зоны, кривой, автоповтора (с записью в `DECISIONS.md`); вид меню и чипа в рамках стиля окна; имена модулей и классов; горячая клавиша меню.
