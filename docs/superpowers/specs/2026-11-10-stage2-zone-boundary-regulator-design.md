# Этап 2: зона — граница, регулятор без обгона и без «насоса» зума

Статус: одобрено оператором 2026-11-11, зона — вариант Б (ширина и высота отдельно). Выполнено 2026-11-11 (кроме
площадки); что получилось, что нет и где работа отошла от этой спеки — в конце плана и в `docs/DECISIONS.md`,
«Этап 2: зона — граница». Главное расхождение: «позднее знание» на стенде оказалось 0,6–0,8 с, а не 0,3–0,45 с. Макет: `docs/design/mockups/zone-boundary.html`.
Основание: запись F9 2026-11-10, живые замеры `docs/field/2026-11-10-live.md`, цели `tests/control/test_operator_eye.py`.

## Зачем

Оператор видит на записи и на живой камере: камера обгоняет остановившегося человека, человек оказывается у края кадра,
зум ходит «отъехал — наехал», при проходе наискось голова уходит по высоте. И главное требование оператора:
«Я сам задаю зону, из которой не хочу выпускать человека» — от размера зоны должна зависеть работа слежения.
Сейчас масштаб зоны меняет только мёртвую зону и крутизну кривой; пороги «пошёл», «догонять», «отъехать» от неё не зависят.

**Не цель:** своя нейросеть (см. «Вариант: своё обучение»), узнавание человека среди нескольких, слежение по H.264,
новые окна. Инварианты безопасности (`AGENTS.md`) и сторож раскачки не меняются.

**Провал, даже если тесты зелёные:** поведение подогнано под один маршрут (на отложенных номерах хуже, чем на
настроечных, больше чем на четверть); камера стала дёрганой; пороги ослаблены вместо исправления; на живой камере
появилась раскачка.

## Что измерено сейчас

Стенд (`tests/control/test_operator_eye.py`, 8 настроечных маршрутов по 60 с, «Пояс», камера как HE42 через настоящий
планировщик, шум 0,004, опросы раз в 0,75 с). Доли кадра.

|---|---|---|---|---|---|
| ровно | 4,3 | 47 % | 0,36 / 0,53 | 4,5 % | 0,12 |
| ровно, отказы камеры 16 % | 3,9 | 56 % | 0,42 / 0,53 | 6,2 % | 0,15 |
| диагональ | 3,9 | 46 % | 0,36 / 0,47 | 4,4 % | 0,55 |

Живые AW-HE40 (клуб, 2026-11-10, по Wi‑Fi):

- Камера слушается за 0,05–0,07 с и после «стоп» проходит v·0,03–0,07 с. Модель регулятора считает 0,08 + τ 0,10–0,12:
  втрое медленнее настоящей.
- «Команда → кадр получен»: MJPEG (1) 0,18–0,23 с, MJPEG (2) 0,28–0,36 с, H.264 ≈ 0,39 с. Значит, само видео опаздывает
  на ≈ 0,15 / 0,25 / 0,33 с. В коде по умолчанию 0,12 / 0,26 / 0,6 (`he42.VIDEO_LATENCY_S`), а у камер клуба после
  мастера калибровки записано 0,079 / 0,26: для MJPEG (1) мастер намерил вдвое меньше прямого замера. Какое число
  верное, не выяснено (мастер калибровали 2026-11-06, прямой замер — по Wi‑Fi) — см. «Риски».
- Живой прогон «Пояс»: зум едет 45 % времени, 3,4 цикла/мин; размер человека `u` за 2,5 с падал в 5–6 раз
  (0,235 → 0,035), когда человек вставал боком и наклонялся. В симуляторе человек всегда стоит лицом.
- Все 14 уходов дальше 0,15 от метки — камера стояла или отставала. Отказов команд 0 из 2686.

### Причины

1. **Позднее знание, а не инерция.** Камера узнаёт о старте и остановке человека через `T` = задержка видео + полкадра
   анализа + окно оценки скорости + очередь и отклик камеры: ≈ 0,3 с на MJPEG (1), ≈ 0,45 с на MJPEG (2), ≈ 0,5 с на
   H.264. За это время человек проходит v·T. Регулятор закладывает «тормозной путь камеры», которого у HE40 почти нет,
   а v·T — нет. Отсюда обгон на остановке и уход к краю на старте.
2. **Старт медленный по построению.** Упреждение растёт с постоянной 0,3 с, ускорение ограничено 1,0 кадра/с², резкий
   догон включается по порогам 0,14–0,30 кадра от метки, не зависящим от зоны.
3. **Зум верит размеру, который врёт.** `u = max(нос→плечи, 0,375·ширина плеч)` сжимается при повороте боком и наклоне —
   регулятор наезжает. На крупном плане любой быстрый шаг даёт прогноз ухода за 0,4 кадра — регулятор отъезжает.
   Через 1–3 с наезд разрешён снова. Это и есть «насос».
4. **Наклон — ось второго сорта.** Срочный догон разрешён только по горизонтали; на диагонали голова уходит на полкадра.
5. **Зона ни на что не влияет.** Пороги «идёт / стоит» (0,05–0,24 кадра), догона, отъезда заданы числами в кадре.

## Как должно работать

Словами оператора — пять правил (они же на макете):

1. Точка — где держать лицо. Внутренняя рамка — покой: пока лицо в ней, камера стоит.
2. Скобки — граница. Чем ближе человек к границе и чем быстрее к ней идёт, тем раньше и сильнее едет камера.
3. Идущего камера держит чуть впереди точки (со стороны, куда он идёт): остановится — камера докатится до точки, а не
   проскочит.
4. Наклон ведёт так же, как поворот.
5. Зум не дёргается: наезжает, когда человек в зоне и размер устойчиво не тот; отъезжает раньше срока, только если
   человек уходит уже из самого кадра и поворотом не успеть.

### Устройство (для исполнителя)

Обозначения по одной оси, в долях кадра: `e` — положение человека относительно точки (прогноз на «сейчас»), `v` —
его скорость в кадре с весом «идёт» `w`, `T` — позднее знание. `B` — полуразмер границы: нынешняя «мягкая зона»
(`soft_x` / `soft_y`, скобки на видео); `d` — полуразмер покоя: нынешняя «мёртвая зона» (`dead_x` / `dead_y`,
внутренняя рамка). Обычная зона — `B` = 0,22 × 0,18, `d` = 0,05 × 0,045 (значения «Обычно») для всех крупностей; размер
зоны оператора умножает оба. Граница не выходит за край кадра минус 0,06.

- **`T` считается, а не угадывается.** `T = задержка видео + ½·период замеров + задержка оценки скорости + отклик
  камеры`. Период замеров берётся из фактического прихода кадров (скользящее среднее), задержка оценки — из числа
  замеров, по которым `PersonEstimator` замечает старт и остановку. Постоянные камеры для HE40 — отдельным профилем
  модели, который выбирается по имени модели (мёртвое время 0,05, τ 0,05 ⚠ по замерам 2026-11-10; у HE42 остаются
  0,08 и 0,12); задержка видео по умолчанию — 0,15 с для MJPEG (1) и 0,25 с для MJPEG (2) (это только видео, период
  кадров считается отдельно), для H.264 остаётся 0,6 до замера по кабелю. Мастер калибровки её по-прежнему меряет сам.
- **Запас вместо тормозного пути.** Цель по положению для идущего — не точка, а `e* = clamp(LEAD·w·v·T, ±0,6·B)`:
  человек впереди точки на столько, сколько камера проедет, пока узнает об остановке.
- **Скорость = скорость человека + поправка.** Базовая скорость камеры — `w·v` (без отдельной постоянной роста), поправка —
  по `e − e*` той же гладкой кривой `speed_for_error`, но не больше скорости, с которой камера успеет затормозить на
  оставшемся пути: `√(2·a_торм·|e − e*|)`. Это заменяет `FF_RISE_S`, `RETURN_V_MAX`, `FB_WALK_*`, `FB_EDGE_*`.
- **Ускорение — по времени до границы.** Обычно — плавность характера (`a_max`, `j_max` ползунка «Мягко … Резко»).
  Нужное ускорение, чтобы человек не пересёк границу: `a_нужно = v_отн² / (2·(B − |e| − |v_отн|·T_кам))`; разрешённое —
  `max(a_характера, min(a_нужно, a_камеры))`. Это заменяет `CATCH_UP`, `CATCH_UP_RUSH`, `RUSH_*`, `urgency`.
- **Один закон на обе оси.** Наклон получает то же самое; раскачку наклона от ошибок модели зума сдерживают доворот за
  зумом (как сейчас) и редкий зум (ниже). Сторож раскачки — без изменений.
- **«Идёт / стоит» — в долях зоны.** Порог «ушёл от места» в `PersonEstimator` — не больше 0,6·B (сейчас до 0,24 кадра):
  в плотной зоне камера трогается раньше. Размах переминания больше 0,6·B — камера ходит за переминанием: это выбор
  оператора, он виден на макете.
- **Размер для зума.** (а) К двум мерам добавляется длина корпуса «плечи → бёдра» (3,3 U — по шкале тела в
  `composition.py`: плечи 1,0, бёдра 4,3), берётся наибольшая из видимых; бёдер не видно — две прежние меры. (б) Размер в регуляторе растёт сразу, а падает не быстрее, чем человек может отойти (предел скорости спада),
  если спад не держится дольше ~1,5 с. (в) Наезд начинается, когда ошибка размера держится дольше ~2 с и человек внутри
  зоны; после отъезда «от края» — не раньше, чем человек ~4 с спокойно в зоне. (г) Отъезд «от края» — только по прогнозу
  выхода за край **кадра** (а не за 0,4 от точки) при повороте на пределе.
- Пауза перед разворотом, доводка в покое, поиск пропавшего (`LOST_COAST_S`) остаются.

Числа со знаком «~» и `LEAD` подбираются только на настроечных маршрутах и записываются в `docs/DECISIONS.md`.
Начальные значения — в плане (`LEAD` 0,8; терпение наезда 2 с; покой после отъезда 4 с; спад размера 0,15 ln/с и
1,5 с). Подбор заканчивается, когда цели приёмки выполнены на настроечных маршрутах; дальше числа не трогают и
запускают отложенные. Пороги «идёт / стоит» внутри `PersonEstimator` (`RUSH_*`, `SPEED_*`) остаются — уходят только
одноимённые пороги догона в `framing.py`. Должны остаться зелёными без ослабления: `test_tracking_goals.py`,
`test_follower.py`, `test_framing.py`, `test_speed_adapt.py`, `test_person_estimator.py`.

## Зона в интерфейсе

Макет `docs/design/mockups/zone-boundary.html`: живая модель, три размера зоны, таблица честного предела.

- Рисунок зоны не меняется (скобки, рамка покоя, точка). Меняется смысл скобок и плашка при перетаскивании: размер
  зоны в процентах и что она значит для текущего потока («удержит и быстрый шаг» / «только спокойный шаг»).
- Честный предел: при резком старте человек проходит v·T до того, как камера тронется (на «Поясе» 0,35 кадра/с:
  ≈ 10 % кадра на MJPEG (1), ≈ 16 % на MJPEG (2)). Плотнее этого зона не удерживается — программа об этом пишет, а не
  обещает.
- **Решение оператора 2026-11-11 — вариант Б.** Вопрос был: размер зоны одним числом, как
  сейчас (А), или ширина и высота отдельно (Б, советую: «широко
  по сцене, узко по высоте»). Б меняет запись зоны в настройках (`[x, y, масштаб]` → `[x, y, ширина, высота]`, старые
  записи читаются) и перетаскивание за угол скобки.
- Ползунок «Мягко … Резко» отвечает за плавность (ускорение, рывок, кривая), размер зоны по умолчанию от него больше
  не зависит ⚠ (решение автора: иначе два органа управления меняют одно и то же).

Новые мерила: «за границей зоны» — доля времени, когда голова по горизонтали дальше `B` от точки (зона — с учётом
размера, заданного оператором); «глубина» — наибольший выход за `B`; «доля движения» — время, когда команда поворота
быстрее 0,01 кадра/с. Точные определения и генератор «поворотов боком» — в плане, задача 1.

## Стенд: чего в нём не хватает

- Человек, который поворачивается боком и наклоняется: «падения» размера в 2–5 раз на 1–3 с и сдвиг головы по высоте.
- Камера как живая HE40 (быстрее модели) при калибровке «как раньше», и наоборот; три набора «поток»: задержка видео и
  частота замеров 0,15 с / 25 к/с, 0,15 с / 15 к/с, 0,25 с / 12 к/с.
- Зоны ×0,5 / ×1 / ×1,8, точка не в центре («Пояс · слева»), «Рост».
- Диагонали круче (наклон пути ±0,8) и с разной глубиной — «камера висит как придётся».
- Мерила: доля времени за границей зоны, глубина выхода, доля времени движения камеры.

## Этапы

1. Стенд и цели (падающие тесты, базовая линия).
2. Время: `T`, постоянные HE40, задержки по потоку.
3. Закон оси: запас, скорость человека, ускорение по времени до границы — поворот.
4. Тот же закон для наклона; диагональ.
5. Зона: пороги «идёт / стоит» от зоны, запись ширины и высоты (если Б), плашка по макету.
6. Зум: размер, терпение, отъезд в крайнем случае.
7. Отложенные маршруты, медленный набор, возврат порогов, документы, независимое ревью.
8. Площадка: оператор ведёт, агент наблюдает и сохраняет записи — «Пояс» на MJPEG (1) и MJPEG (2), «Рост», один прогон
   с плотной зоной; камера не в эфире.

## Риски

- **Упреждение со скоростью человека раскачивает камеру, если модель камеры неверна** (поэтому сейчас рост 0,3 с).
  Защита: модель идёт по реально ушедшим командам (`pt_sent`), постоянные исправлены по замерам, тесты с ошибкой скорости
  ×0,5…×2 и задержки ±0,1 с, сторож не тронут. Не сходится — рост упреждения остаётся ограниченным, цель обгона
  пересматривается с оператором, а не подгоняется.
- **Плотная зона = беспокойная камера.** Это показано на макете до кода; предел пишет плашка.
- **Запас «впереди точки» оператор может принять за отставание.** Показано на макете (п. 5); `LEAD` — одно число, можно
  убавить.
- **Задержка видео у камер клуба: мастер 0,079 с, прямой замер ≈ 0,15 с.** Регулятор верит мастеру. В задаче 2 —
  проверка мастера на симуляторе с известной задержкой; на площадке — перекалибровка и повтор прямого замера по
  кабелю. Пока не выяснено, стенд проверяет обе ошибки (задержка в регуляторе меньше и больше настоящей на 0,1 с).
- **Замеры HE40 сняты по Wi‑Fi.** По кабелю задержки меньше — перемерить; регулятор берёт `T` из измеренного, а не из
  таблицы.
- **Подгонка.** Только настроечные номера при подборе; отложенные — в конце, расхождение > 25 % — возврат к закону.

## Вариант: своё обучение (после этапа 2, отдельной спекой)

Смысл — сократить `T`: предсказывать «сейчас пойдёт / сейчас встанет» по позе (наклон корпуса, шаг) за 0,2–0,3 с до
того, как это видно по положению. Учить можно на своих записях F9 без ручной разметки: ответ — куда человек сместился
через 0,3 с в той же записи. Вход — когда после этапа 2 цели обгона или края не достигаются из-за `T` на MJPEG (2) или
оператору нужна зона плотнее честного предела. Нужно: несколько часов записей с ходьбой, лицензия своей модели — AGPL.

## Решения автора спеки (оператор может поправить)

- Зона по умолчанию не зависит от ползунка «Мягко … Резко».
- Порог «ушёл от места» — 0,6·B; запас впереди точки — не больше 0,6·B.
- Новые пороги приёмки для зоны: 3 % времени и 0,06 глубины — мой выбор по честному пределу MJPEG (1).
- Отъезд «от края» считается от края кадра, а не от точки.
- Своё обучение — не в этом этапе.
