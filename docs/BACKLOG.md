## Ждём с площадки (этапы 1–3 + шаг А)

1. Подключить MacBook к сети камер, запустить `run_mac.command`, вести докладчика 2–3 минуты. Когда цель перескочит, камера дёрнется или уедет — нажать **F9**.
2. Прислать zip из папки «Записи PTZ Tracker» (рабочий стол). Каждый плохой эпизод становится тестом повтора и входом шага Б.
3. Если ноутбук можно оставить в сети, пока камера не в эфире, агент сам проведёт калибровку и пробное слежение (`--lab`).

- Отзыв о слежении: где дёргается, где отстаёт, удобное положение «Мягко ↔ Резко». По нему подстраиваются `control/effort.py` и `camera/he42.py`.
- Результат мастера калибровки на живой камере: `CameraConfig.calibration` в `%APPDATA%\PTZTracker\config.json`. По нему видно, включено ли у камеры «Speed With Zoom» и насколько точна таблица по умолчанию.
- Сработал ли где-то сторож раскачки («камера раскачивалась…»).
- Соответствие `#GZ` → масштаб картинки на живой HE42. Модель зума регулятора считает его линейным по ln масштаба, 20× (`he42.ZOOM_RATIO`, как в симуляторе). Если на площадке это не так, поправка по `#GZ` будет тянуть модель не туда — снять несколько положений `#AXZ` и масштаб картинки.

## Шаг Б — исправление слежения (по записям)

- **Геометрия симулятора (отзыв пользователя, 2026-10-21).** Симулятор и тесты не учитывают геометрию: реальный поворот — не сдвиг картинки без искажений (перспектива при вращении, дисторсия объектива, зависимость от зума). Нужно рисовать сцену проективно (гомография по углам pan/tilt + дисторсия) и перепроверить калибровку (фазовую корреляцию) и тесты регулятора на ней.
- **Шкала `#APC` и угол обзора живой HE42 (часть 1, задача 3).** Мастер калибровки теперь меряет скорости по `#APC` и переводит их в доли кадра через `he42.APC_DEG_PER_UNIT` (0,0075° — шкала симулятора) и паспортный угол обзора (`he42.hfov_deg`). На живой камере ни то ни другое не мерилось; если мастер напишет «по картинке камера повернулась на N% от того, что сообщает сама», — прислать отчёт и записать в `he42.py` настоящие значения (шкалу сверить с документацией протокола Panasonic: крайние значения `#APC` для ±175°). Время мастера выросло до ~3–4 минут (возврат и ожидание покоя перед каждым пробегом).
- **Замечания оператора к слежению:** цель перескакивает на других людей; композиция «Пояс» отъезжает почти полностью и теряет цель; кадрирование целится в живот, а не в лицо; зоны должны редактироваться пользователем; подстройка скорости должна идти в ходе слежения.
- **Сторож раскачки: «человек стоит, камера ходит» (часть 1, задача 2).** Второе правило ловит качание при стоящем человеке по положению человека «в мире» между разворотами в одну сторону и пробегу камеры больше мягкой зоны. Оно же останавливает слежение, когда человек переминается ±0,06 кадра и камера раскачивается в 2,5–5 раз шире него («Обычно», «Резко»). Если на площадке это выключит слежение за человеком, который просто переступает с ноги на ногу, — сравнивать по настоящему положению камеры (`#APC` → доли кадра по углу обзора), а не по модели.
- **Подтверждение разворотов по `#APC`** работает, только пока идёт запись (опрос положения — для записи, раз в 0,5–1,5 с); без записи сторож решает по командам. Порог «камера проехала» `WATCHDOG_APC_MIN_STEP` = 3 единицы — по шкале симулятора (0,0075°), на живой HE42 шкалу `#APC` не мерили. Частоту опроса настраивает задача 7.
- **Повтор распознавания** видит сохранённые 5 к/с, а живой анализ идёт ~15 к/с, поэтому числа потерь цели различаются. Вариант: писать кадры в темпе анализа (в ~3 раза больше памяти и zip) — нужно решение пользователя.

## Этап 4 — поведение (по спеке §9, §13)

1. **Поиск при потере цели.** Камера ждёт ~2 с, потом плавно отъезжает шире и узнаёт цель по внешности. Через N секунд поиска — пресет «общий план» и крупная надпись «ЦЕЛЬ ПОТЕРЯНА».
2. **Перехват пультом.** Опрос `#APC`/`#GZ` в свободных окнах планировщика, сравнение с моделью камеры; расхождение → слежение на паузу, в статусе «ПУЛЬТ». Возобновление по умолчанию — по кнопке.
3. **Автовозобновление после ручного вмешательства** (настройка: через паузу или только по кнопке).
4. **«Своя зона»:** рамка на превью → пресет композиции.
5. **Классический трекер (CSRT/KCF) и гибрид** «нейросеть раз в N кадров + трекер между».
6. **Слежение за группой и быстрые сцены** (концерты, танцы) — второстепенно.

Этап 5 — площадка и донастройка; затем несколько камер одновременно (архитектура: несколько `CameraSession`).

## Отложенные мелочи

**Камера и сеть**
- На Windows `cv2.imwrite`/`VideoCapture` молча падают на путях с кириллицей: в отчёте диагностики может не оказаться кадров. Использовать `imencode` + `write_bytes`.
- `NotificationListener` открывает порт с `SO_REUSEADDR`; на Windows нужен `SO_EXCLUSIVEADDRUSE`.
- `AuthRequired` показывается как «нет связи» вместо «неверный логин/пароль».
- В RTSP таймаут чтения равен таймауту открытия (5 с): зависший поток до 5 с показывает застывший кадр как «на связи». `thread_type="AUTO"` может добавлять задержку кадров.
- Кнопка «Проверить связь» остаётся на «Проверяю…» при неожиданном исключении (например, `httpx.InvalidURL`).
- `CameraSession.stop()` не закрывает HTTP-клиент: небольшая утечка при смене камер.
- Диалоги, привязанные к главному окну, не удаляются после закрытия.
- Маскировка очень короткого пароля портит текст отчёта.

**Распознавание**
- Внешность трека при создании берётся без проверки на перекрытие: цель, выбранная в толпе, может «впитать» соседа.
- При смене камеры или потока модель загружается заново (на время дважды занимает память видеокарты).
- Рамки рисуются по последнему анализу и отстают от идущего человека на один цикл.
- «анализ: загрузка модели…» показывается и тогда, когда просто нет видео.

**Слежение**
- Скорость наклона не калибруется (считается равной скорости поворота). `TILT_FROM_FH` и зоны на превью не учитывают пропорции кадра.
- Модель зума (`zdyn`) не сверяется с фактическим `#GZ`, кроме упоров объектива.
- Мастер калибровки шлёт команды мимо планировщика, пока работает проверка связи: интервал 130 мс не гарантирован.
- Диагностика возвращает камеру после замера задержки по числу удачных замеров, а не по числу отправленных движений. Важно только для камер без запроса положения.
