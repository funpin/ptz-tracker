# Версии и релизы

Проект дорабатывается редко и порциями: донастройка на реальных данных и площадке, отдельные функции. Поэтому правила простые.

## Номер версии

`MAJOR.MINOR.PATCH`, по [SemVer](https://semver.org/lang/ru/). Пока программа не проверена на площадке как готовая к эфиру, `MAJOR = 0`.

| Что изменилось | Что увеличить | Пример |
|---|---|---|
| Исправления, донастройка порогов и калибровки по замерам, тексты, документация к сборке | `PATCH` | 0.2.0 → 0.2.1 |
| Новая возможность для оператора или заметная смена поведения: шаг Б (слежение по записям), границы сцены, запись видео, две камеры | `MINOR`, `PATCH` = 0 | 0.2.1 → 0.3.0 |
| Программа проверена на эфире и пользователь сказал «готово» | `1.0.0` | 0.x → 1.0.0 |
| После 1.0: несовместимые настройки (`config.json` не читается старой версией) | `MAJOR` | 1.4.2 → 2.0.0 |

Один номер — в `src/ptztracker/__init__.py` (`__version__`). Его же читают `pyproject.toml` и сборка `.app`.

## Когда выпускать

Релиз выпускают, когда пользователю есть что поставить на площадке: законченная порция работы, все тесты зелёные. Каждая правка отдельного релиза не требует: изменения копятся в разделе `[Не выпущено]` в `CHANGELOG.md`.

Релиз выпускают только по просьбе пользователя или с его согласия: тег и релиз видны всем.

## Как выпустить

1. В `CHANGELOG.md` переименуйте `[Не выпущено]` в `[X.Y.Z] — ГГГГ-ММ-ДД` и добавьте сверху пустой `[Не выпущено]`. Пишите для оператора: что изменилось на площадке, что сделать (откалибровать заново, прислать запись).
2. Поставьте `__version__ = "X.Y.Z"`.
3. Прогоните полный набор `.venv/bin/pytest -q` и `ruff`.
4. Коммит `release: vX.Y.Z`, затем тег и push:

   ```bash
   git tag -a vX.Y.Z -m "PTZ Tracker X.Y.Z"
   git push origin main vX.Y.Z
   ```

5. Workflow `Release` (`.github/workflows/release.yml`) сверит тег с `__version__` и `CHANGELOG.md`, соберёт `PTZTracker-X.Y.Z-windows-x64.zip` и `PTZTracker-X.Y.Z-macos-arm64.zip`, прогонит быстрые тесты и создаст релиз. Заметки берутся из раздела версии в `CHANGELOG.md` и `docs/release-footer.md`.
6. Проверьте страницу релиза: оба файла на месте. Пользователю дайте ссылку и коротко скажите, что сделать на площадке.

Если сборка упала, тег не переиспользуйте: исправьте ошибку и выпустите `X.Y.(Z+1)`.

## Что не делаем

- Не подписываем приложения сертификатами (нет аккаунтов Apple Developer и подписи кода Windows). Как открыть неподписанное приложение — в `docs/release-footer.md`.
- Не собираем под Intel Mac: целевой Mac — Apple Silicon.
- Не ведём ветки релизов: всё идёт в `main`.
