# Архитектура PTZ Tracker

Программа для Windows (PySide6): управляет PTZ-камерами Panasonic AW-HE42 по HTTP, принимает их видео по сети, находит людей нейросетью и ведёт выбранного человека камерой. Разработка ведётся на macOS: живая камера с машины разработчика недоступна, всё проверяется на симуляторе. Реальные факты приходят от пользователя через «Диагностику камеры».

## Карта модулей (`src/ptztracker/`)

| Пакет | Ответственность | Главные типы |
|---|---|---|
| `config.py` | Настройки в `%APPDATA%\PTZTracker\config.json`, атомарная запись, пароли в `keyring` | `CameraConfig`, `AppConfig`, `ConfigStore` |
| `camera/` | Всё о камере: команды Panasonic, HTTP, очередь команд, сессия одной камеры, замеры HE42 | `protocol`, `CameraClient`, `CommandScheduler`/`Priority`, `CameraSession`, `he42` |
| `video/` | Приём кадров: RTSP/MJPEG через PyAV, подбор рабочего адреса | `Frame`, `FrameSource` (Protocol), `RtspSource`, `stream_urls` |
| `vision/` | Люди на кадре: детектор позы (ONNX), сопровождение и цель, фоновый анализ | `PoseDetector`, `SimDetector`, `PersonTracker`, `Analyzer`, `AnalysisResult` |
| `control/` | Слежение: модель камеры, композиции, усилие, регулятор, поток слежения, мастер калибровки | `Calibration`, `FramingController`, `Follower`, `CalibrationRunner` |
| `sim/` | Виртуальная AW-HE42: та же HTTP-команда, динамика по замерам, синтетическая сцена с разметкой | `SimPtz`, `SimHttpServer`, `SimFrameSource`, `SyntheticStage` |
| `diagnostics/` | Диагностика на площадке → zip-отчёт; общий замер скорости | `run_diagnostics`, `checks`, `probe` |
| `recorder/` | Чёрный ящик: последние минуты кадров и событий, zip-снимки, чтение и повтор эпизодов | `BlackBox`, `NullRecorder`, `Episode`, `replay_controller`, `replay_analysis` |
| `api/` | Локальный HTTP-API для агента (только 127.0.0.1, токен) | `ApiServer`, `WindowBackend`, `QtInvoker` |
| `lab.py` | Команды без окна `--lab record\|follow\|calibrate` для агента | `run_lab` |
| `ui/` | Окна Qt: главное окно, превью с рамками и зонами, панели | `MainWindow`, `PreviewWidget`, `FollowPanel`, `AgentPanel`, `ReplayWindow` |
| `models/` | Модель YOLO11n-pose (ONNX, AGPL-3.0) | `POSE_MODEL_PATH` |

Зависимости идут сверху вниз: `ui` → `control`/`vision`/`camera` → `video`/`sim`. `camera/he42.py` — единственный источник замеров живой камеры (скорости, разгон, задержки). Его читают и `sim`, и `control.camera_model`. Расхождение этих двух мест уже однажды сломало проверку регулятора.

## Поток данных

```
камера ──HTTP #PTS/#Z/#APC…── CommandScheduler (≥130 мс между командами, приоритеты, склейка по ключу)
   │                                   ▲              ▲                       ▲
   └─MJPEG/RTSP→ FrameSource ─latest()→ Analyzer ─AnalysisResult→ Follower ──┘   ручные команды (UI → CameraSession)
                      │                (поток)        │            (поток 25 Гц)
                      └──────────── PreviewWidget ◄───┘ (таймер Qt, только читает)
```

- **`CameraSession`** собирает всё для одной камеры: клиент, планировщик, источник кадров, анализ, слежение. Несколько камер в будущем — это несколько сессий.
- **Потоки:**
  - планировщик команд;
  - приём видео;
  - анализ;
  - слежение (25 Гц) плюс опрос зума;
  - проверка связи;
  - симулятор (HTTP и физика).

  Интерфейс читает их состояние таймерами (`MainWindow._sync_follow`, `_update_status`) и сам никогда не ждёт сеть или нейросеть.
- **`Analyzer.latest()` и `Follower.output`** — неизменяемые снимки: UI их только читает. Трекер меняется только под замком анализатора.

## Чёрный ящик (`recorder/`)

Нужен, чтобы плохой момент на площадке стал файлом, который можно разобрать и повторить без камеры.

- **Запись — только наблюдатель.** `CameraSession` создаёт `BlackBox` (или `NullRecorder`, если запись выключена). Крючки в `CommandScheduler`, `Analyzer`, `Follower`, `CameraSession` зовут `safe_event`/`safe_frame`, которые не бросают исключений и не блокируют: слежение и команды от записи не зависят.
- **Что пишется.** Кадры — 5 к/с, JPEG q70, не больше 640×360. События (`events.py`, `KINDS`): `analysis` (результат анализа), `control` (такт регулятора с входами и кодами), `cmd` (отправленная команда и ответ), `position` (`#APC`/`#GZ`), `follow` (вкл/выкл, причина, `video_latency`), `target`, `note`.
- **Буфер.** Кольцо по времени (`ring.py`), по умолчанию 5 мин. Кадры и события идут разными очередями: при переполнении выбрасываются кадры, события — никогда. Фоновый поток кодирует и складывает; zip пишет ещё один поток, атомарно (`.part` → переименование).
- **Снимок.** F9, пункт меню «Сохранить момент», `POST /moment` или `--lab` пишут буфер в zip: `meta.json`, `events.jsonl`, `frames.jsonl`, `frames/NNNNNN.jpg`. Папка — «Записи PTZ Tracker» на рабочем столе (`record_dir`). Постоянная запись на диск (`record_to_disk`) идёт кусками по минуте.
- **Пароли.** `redact_meta` удаляет ключи `pass/pwd/secret/token` и чистит адреса `redact_url`; `event_line` проверяет каждую строку ещё раз.
- **Положение камеры.** Пока слежение включено, `Follower` опрашивает `#APC`+`#GZ` каждые 0,5 с. Без слежения, но при записи, `CameraSession` делает это раз в 2,0 с и молчит 2,0 с после любой ручной команды (иначе опрос задержит джойстик: камера отвечает ~7 команд в секунду). Во время калибровки опрос и пульс стоят (`quiet_for_calibration` / `resume_after_calibration`; `Follower` не заменяется, `enable()` при паузе отказывает).
- **Чтение.** `Episode.open(zip)` отдаёт `meta`, `events(kind)` и `frames()`; повреждённые строки пропускает и считает (`bad_lines`).
- **Повтор.** `python -m ptztracker --replay файл.zip` — по умолчанию через регулятор (`replay_controller`): записанные такты заново идут через `FramingController`, коды совпадают с записанными (проверено: 0 расхождений на 675 тактах); с другой калибровкой, композицией или `effort` видно, что изменилось бы. Выводит сводку и PNG-графики (`--out`). `--mode analysis` прогоняет сохранённые кадры через детектор и `PersonTracker` и сравнивает цель «было/стало»; `--view` открывает `ReplayWindow`. Задержка видео берётся из события `follow on`.
- **Эпизод-тест.** `tests/data/episodes/sim_walk_30s.zip` и `tests/recorder/test_stored_episode.py`. Плохие эпизоды с площадки кладутся рядом и становятся тестами.

## API для агента (`api/`, `ui/agent_panel.py`)

- **Доступ.** `ApiServer` слушает только `127.0.0.1:api_port` (8765), каждый запрос — `Authorization: Bearer <api_token из config.json>`; токен создаётся при первом запуске. Порт занят — окно работает без API. Токен в лог не попадает.
- **Чтение** (по умолчанию доступно всегда): `GET /status`, `GET /events?since=&limit=`, `GET /frame.jpg`; `POST /moment` сохраняет снимок.
- **Управление:** `POST /follow {"on": bool}`, `/target {"x","y"}`, `/composition {"key"}`, `/effort {"value"}`. `/calibrate` отвечает 501: мастер калибровки — модальное окно, его запускает оператор.
- **Оператор решает флажками панели «Агент»** (выключены по умолчанию, не сохраняются): «Разрешить управление агенту» и «Камера НЕ в эфире». Любая команда, что может двинуть камеру, требует **оба**; `/follow off` — только первый. Без разрешения — 403. Esc, ручное действие, смена камеры, раскачка и аварийный стоп снимают оба флажка.
- **Потоки.** Чтение идёт в потоках сервера и берёт только снимки состояния. Действия `WindowBackend` выполняет в потоке Qt через `QtInvoker` (ждёт до 2 с; Qt сервера не ждёт), поэтому проверка разрешения и действие не разъезжаются с пробелом и Esc. Во время калибровки и при открытом модальном диалоге — 409.
- **Не в эфире.** Когда в программе появится ATEM-тали (ветка `claude/ui-redesign-1bdc78`), API обязан отказывать в движении и при камере в PGM (BACKLOG).

## Команды без окна (`lab.py`)

`python -m ptztracker --lab record|follow|calibrate --ip IP [--user …] [--seconds N] [--select X,Y] [--composition …] [--effort 0..1] [--out папка] [--save] --not-on-air`. Без окна, без Qt. `follow` и `calibrate` двигают камеру только с `--not-on-air` (иначе код 3, к камере не подключаемся). Пароль — из хранилища по камере из настроек или `PTZ_PASSWORD`; в аргументах и выводе его нет (`_scrub`). `--ip sim` — пробный прогон на симуляторе. Последняя строка вывода всегда `RESULT {json}`. Коды выхода: 0 — готово, 1 — ошибка, 2 — неверные аргументы, 3 — нет `--not-on-air`, 4 — в точке `--select` нет человека, 130 — Ctrl+C (аварийный стоп).

## Единицы и знаки (сквозные)

- **Координаты** в регуляторе — доли кадра (0…1).
- **Скорости:**
  - pan — fw/s, доли ширины кадра в секунду;
  - tilt — fh/s, доли высоты (в коды переводится через `TILT_FROM_FH = 9/16`);
  - зум — ln(масштаба)/с.
- **Коды скорости камеры** 01–99, 50 = стоп. Pan > 50 — вправо, tilt > 50 — вверх, zoom > 50 — к теле.
- **Регулятор в «мировых» единицах:** смещение от центра, делённое на масштаб зума. Иначе наезд выглядел бы как ходьба человека.
- **Размер человека** — U, вертикаль «нос → линия плеч», не меньше 0,375 ширины плеч. Опорная точка — над серединой плеч. Наклон и поворот головы камеру не двигают.
- **`Frame.t_capture`** — момент получения кадра программой, а не съёмки. Задержку видео вычитает регулятор: `Calibration.video_latency` по типу потока.

## Инварианты безопасности (эфир)

1. Любое ручное действие (джойстик, зум, стрелки, пресет, фокус), Esc, смена камеры, остановка анализа (результат старше 0,6 с + задержка видео) или раскачка (сторож) **выключают слежение немедленно**. Стопы `#PTS5050`/`#Z50` уходят с приоритетом MANUAL, ручная команда в ту же ячейку их заменяет.
2. Аварийные стопы никогда не отбрасываются (`er2` повторяется, EMERGENCY не ограничен ретраями). Разовые команды (пресет, разовый AF) устаревают через 2 с без связи.
3. Цель потеряна — камера плавно останавливается (~0,5 с) и ждёт. Слежение при этом остаётся включённым.
4. `CameraSession.stop()` не подвешивает UI: стопы ждём, только если камера на связи. Потоки, застрявшие в сети, — daemon.
5. Пароли не попадают в лог, на экран, в отчёт диагностики и в записи чёрного ящика (`redact_url`, `mask`, `redact_meta`).
6. Агент по API двигает камеру только при двух флажках оператора («Разрешить управление агенту» и «Камера НЕ в эфире»); ручное действие, Esc, смена камеры, раскачка и аварийный стоп их снимают.
7. Запись не лежит на пути управления: её сбой или переполнение не задерживают команды и слежение.

## Регулятор (кратко; детали и причины — `docs/DECISIONS.md`)

`FramingController.step()` — чистая функция шага, тестируется в виртуальном времени (`tests/control/loop.py`). По каждой оси:
- компенсация задержки по модели камеры (`CameraDynamics`: мёртвое время + инерция τ);
- скорость человека — наклон за 0,4 с, упреждение с весом 0,5;
- мёртвая и мягкая зоны с гистерезисом; трогаемся, только когда человек вышел из мёртвой зоны;
- медленная доводка после перелёта;
- ограничение ускорения;
- сторож раскачки.

Зум: наезд одним движением, когда человек стоит ≥ 1 с; отъезд сразу у края кадра; поворот подстраивается под наезд. `Follower` переводит скорости в коды по `Calibration` (таблица «код → fw/s» по зумам) и шлёт через планировщик: TRACKING для поворота, TRACKING_ZOOM для зума (поворот важнее).

## Тесты

- **Быстрый набор** `pytest -m "not slow"` — около минуты: протокол, планировщик, модели, регулятор в виртуальном времени, UI на offscreen-Qt.
- **`slow`** — реальное время на симуляторе: замкнутый контур, слежение, калибровка, диагностика. Полный прогон ~9 мин. Под нагрузкой эти тесты изредка нестабильны; это граничные метрики, а не логика.
- **Виртуальный стенд** `tests/control/loop.py` умеет: рассогласование скорости камеры (`speed_factor`), задержку очереди (`cmd_delay`), зум у края объектива. Новые свойства регулятора проверяются сначала им.

## Известные слабые места

- `ui/main_window.py` (~500 строк) собирает слишком много: список камер, горячие клавиши, связь панелей со слежением. Кандидат на разделение при следующем расширении UI.
- **Симулятор совпадает с моделью регулятора по построению.** Ошибки калибровки на нём не видны, их ловит только виртуальный стенд с `speed_factor`.
- **У конфига нет номера версии схемы.** Новые поля добавляются со значениями по умолчанию; переименование полей потребует миграции.
- **Нет проверки типов (mypy).** Регресс по типам ловят тесты; numpy-числа из ключевых точек уже однажды сломали арифметику со знаками.
